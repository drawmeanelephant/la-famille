point at the generated site, which the server never serves.

  is neither an embedded UI asset nor "/", then falls back to the UI shell.
- No directory listings: only exact files and `<dir>/index.html` are served.

## Issue #422 — case-only output collisions

**Decision (operator, defaulting to the recommended middle option):** probe the
output filesystem once; hard-fail case-only collisions only where the collision
is real (case-insensitive FS), warn + proceed where the FS is case-sensitive.

- `probeCaseSensitivity(dir)` — one-file probe (create probe file, stat
  case-flipped spelling; distinct file => case-sensitive).
- `outputClaims` keys stay case-folded, but values become owner lists; exact
  duplicates always collide; case-only duplicates collide when the FS is
  case-insensitive and become warnings otherwise.
- Warnings flow into `BuildResult.Warnings` (persisted in the build cache).

## Static pipeline impact

Build output on case-sensitive filesystems can now contain paths differing only
in case (previously a hard error). Exact-duplicate collisions are still errors
everywhere. No template/asset/config changes.

## Tests

- generator: deterministic via injectable `detectCaseSensitivity` var —

  with warning + both files published; asset case-only collision follows the
  same rule; exact duplicates still rejected (unit test).
